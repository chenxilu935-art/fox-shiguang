# 旧主题 JSON 兼容预览

## 旧版结构

旧拾光室主题文件 `shiguang-topics.json` 使用 v1 格式。下例为虚构数据。

```json
{
  "version": 1,
  "revision": 7,
  "categories": [{ "id": "tools", "name": "工具" }],
  "assignments": {
    "xhs:000000000000000000000001": ["tools"],
    "demo:sample": ["tools"]
  }
}
```

- `categories` 的数组顺序即旧分类顺序。旧定义保存稳定 ID 与名称。
- `assignments` 从旧文章键映射到主题 ID 数组。小红书键包含 24 位十六进制原帖 ID，`demo:` 键用于旧演示记录。
- `revision` 是旧主题文件的非负整数操作计数。旧写入串行执行，每次操作校验调用方的 revision 和磁盘文本，随后通过临时文件原子替换。预览显示源 revision，供以后确认迁移时核对。

## 在隔离 Vault 预览

1. 打开插件的原生设置，在「数据与关于」选择「预览旧主题导入」。
2. 选择一份自行保存的旧主题 JSON 副本或虚构样本。插件仅访问所选文件。
3. 展开主题与文章分组，核对拟新增主题、已有主题、命名与 ID 冲突、拟获得关联的文章、已有 Markdown 属性及未匹配记录。

文章按原帖 ID 与当前 Inbox 和 Bookmarks 比对。出现重复原帖 ID 时列出全部候选路径，留待确认。已有的 `shiguangTopics` 一律保留，包括空列表及未知格式。演示键和没有文章匹配的历史记录单独显示并保留在原 JSON。本阶段预览不会写入设置或笔记，不会迁移或删除旧 JSON。

## 后续一次性导入

体验验收后再开启导入写入。确认前重新比对源 revision、主题设置和每篇文章的当前 frontmatter，预览发生变化时应重新确认。备份旧 JSON、插件设置和涉及的 Markdown。沿用安全的新分类 ID 和已存在的匹配定义，冲突项由用户处理。仅给唯一匹配且尚无 Markdown 主题属性的文章写入 `shiguangTopics`。逐篇记录成功与失败，以备重试或从备份恢复；已经存在的字段继续保留。导入结束后，关联通过 Markdown 单独维护，未匹配的旧键仍可从原 JSON 查询。
